ChartDeck by OpenUnlock is an open-source Apache-2.0 wrapper and fork of kanaries/graphic-walker, created to unlock a full BI workflow and multi-provider AI analytics without SaaS paywalls. Upstream copyright and Apache-2.0 notices are preserved. Wrapper additions are documented in ATTRIBUTION.md.

Set up your own AI
in a few steps.

AI prompts are sent directly from this browser to the provider you select. Dataset rows are not included in AI requests.

✳

Get a free Gemini key

  1. Create a key in Google AI Studio (availability and free-tier quotas depend on your region/account).
  2. Open ChartDeck, choose BYOK AI Settings → Google Gemini, paste the key, and select gemini-2.5-flash or gemini-2.5-pro.
  3. To enable Google profile sign-in, create a Web OAuth client in Google Cloud Console, add https://chartdek.vercel.com as an authorized JavaScript origin, and set NEXT_PUBLIC_GOOGLE_CLIENT_ID in the Vercel project.

The key stays in this browser's localStorage, but page JavaScript can read it. Use a restricted key and a trusted browser profile.

▧

Connect a self-hosted Ollama

  1. Run Ollama on a machine reachable from your browser and pull a model such as qwen2.5-coder or llama3.2.
  2. Place a TLS reverse proxy or Cloudflare Tunnel in front. Never expose an unauthenticated Ollama port to the public internet.
  3. In settings, enter the public Base URL, Custom Port (leave blank when proxied over 443), exact Model name, and a strong Passkey.
OLLAMA_HOST=0.0.0.0:11434
OLLAMA_ORIGINS=https://chartdek.vercel.com

Allow CORS preflight and the Authorization, Content-Type, and X-API-Key headers. ChartDeck sends the passkey as Authorization: Bearer … and X-API-Key. For Nginx, proxy to 127.0.0.1:11434, pass those headers upstream, and answer OPTIONS with an allowlisted ChartDeck origin. For Cloudflare Tunnel, use an HTTPS hostname and an authentication policy that permits browser preflight; keep Ollama itself private.

The browser connects directly to your configured Ollama URL. Use HTTPS, restrict allowed origins, and keep the model route behind authentication.
